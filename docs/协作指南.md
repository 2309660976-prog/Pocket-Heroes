# Pocket Heroes 协作指南

本项目使用 Git 保存历史，GitHub 用于交换代码和审查修改。仓库是公开的；任何人都能查看和克隆代码，只有仓库所有者及获得写入权限的人能直接推送。

## 第一次加入项目

1. 注册并登录自己的 GitHub 账号；不要共用账号或密码。
2. 安装 Git、C++ 编译器和 SFML 3.1。项目使用 C++17，Windows 下可使用 MSYS2 的 g++ 和 SFML 3.1。
3. 打开 PowerShell，克隆项目：

   ```powershell
   git clone https://github.com/2309660976-prog/Pocket-Heroes.git
   cd Pocket-Heroes
   ```

4. 如果 `g++` 和 SFML 未设置为脚本默认路径，在当前 PowerShell 窗口指定自己的安装位置：

   ```powershell
   $env:CXX = "C:\你的MSYS2目录\ucrt64\bin\g++.exe"
   $env:SFML_ROOT = "C:\你的SFML目录\SFML-3.1.0"
   .\build.ps1
   .\build\PocketHeroes.exe
   ```

   `SFML_ROOT` 应指向包含 `include`、`lib` 和 `bin` 的目录。VS Code 的 `.vscode/c_cpp_properties.json` 目前包含项目创建者的本机路径；朋友使用 VS Code 时，也要把里面的 SFML 头文件路径和编译器路径改成自己的路径。`build/` 是本地编译产物，不提交到 GitHub。

## 每次修改代码

先在本机同步 `main`，然后给自己的改动创建一个分支。下面的 `monster-health` 只是分支名示例：

```powershell
git switch main
git pull --ff-only origin main
git switch -c feature/monster-health
```

修改后先运行 `git status`，确认将提交的文件；再编译、提交和推送：

```powershell
.\build.ps1
git status
git add src/Monster.cpp src/Monster.hpp
git commit -m "加入小怪生命值"
git push -u origin feature/monster-health
```

在 GitHub 仓库页面点击 **Compare & pull request**，目标分支选 `main`。写清改了什么、如何测试；另一位开发者检查后合并。这个流程能在合并前发现问题，也方便双方学习代码。

分支合并后，本机再次运行 `git switch main` 和 `git pull --ff-only origin main`。下次改动新建另一个分支。两人尽量不要同时修改同一个文件的大段内容；若出现冲突，先沟通要保留的逻辑，再在本机解决冲突并重新编译。

## 邀请朋友直接协作

仓库所有者打开 GitHub 仓库页面，依次进入 **Settings → Collaborators → Add people**，输入朋友的 GitHub 用户名并发送邀请。朋友接受邀请后可以向仓库推送分支。公开仓库即使不邀请，朋友也可以 Fork 仓库并向本项目发起 Pull Request。

不要把密码、访问令牌、个人配置或 `build/` 里的可执行文件提交到仓库。提交前用 `git status` 核对文件清单。

GitHub 官方说明：[邀请协作者](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository)、[创建 Pull Request](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request)。
